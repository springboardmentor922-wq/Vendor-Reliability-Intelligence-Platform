# API Reference

> **Full interactive documentation** is auto-generated by FastAPI and available at [`http://localhost:8000/docs`](http://localhost:8000/docs) (Swagger UI) and [`http://localhost:8000/redoc`](http://localhost:8000/redoc) when the backend is running.
>
> This document provides a **group-level overview** of every endpoint namespace. Refer to `/docs` for request/response schemas, authentication requirements, and example payloads.

---

## Base URL

| Environment | Base URL |
|---|---|
| Local (manual) | `http://localhost:8000/api/v1` |
| Docker Compose | `http://localhost:8000/api/v1` |
| Production | `https://<your-domain>/api/v1` |

All endpoints require a valid **Bearer JWT** in the `Authorization` header unless marked *(public)*.

---

## Endpoint Groups

### 🔐 Authentication — `/api/v1/auth`
Registration, login, token refresh, logout, and current-user profile.

| Method | Path | Description |
|---|---|---|
| POST | `/auth/register` | Register a new user account *(public)* |
| POST | `/auth/login` | Obtain access + refresh tokens *(public)* |
| POST | `/auth/refresh` | Exchange a refresh token for a new access token |
| POST | `/auth/logout` | Revoke the current refresh token |
| GET | `/auth/me` | Return the currently authenticated user's profile |

---

### 🛡️ Admin — `/api/v1/admin`
User management and approval workflow (Administrator role only).

| Method | Path | Description |
|---|---|---|
| GET | `/admin/users` | List all registered users |
| PATCH | `/admin/users/{id}/approve` | Approve a pending user registration |
| PATCH | `/admin/users/{id}/reject` | Reject a pending user registration |
| DELETE | `/admin/users/{id}` | Delete a user account |

---

### 🏢 Vendors — `/api/v1/vendors`
Vendor master data, status management, contacts, and cascading delete.

| Method | Path | Description |
|---|---|---|
| GET | `/vendors` | List vendors (filterable by status/category) |
| POST | `/vendors` | Create a new vendor record |
| GET | `/vendors/{id}` | Retrieve a single vendor |
| PUT | `/vendors/{id}` | Update vendor details |
| PATCH | `/vendors/{id}/status` | Update vendor status (ACTIVE / INACTIVE / etc.) |
| DELETE | `/vendors/{id}` | Delete a vendor and all associated data |
